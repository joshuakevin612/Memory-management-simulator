> PAGING & VIRTUAL MEMORY

WHAT IT SHOWS: A process has 8 pages of 256 bytes (logical addresses 0 to 2047). RAM has only 4 frames of the same size. The page table records which frame holds each page. Pages not in RAM sit "on disk". That is virtual memory: the process thinks it has all 8 pages.
HOW TO USE: 1) Type an address (0 to 2047) and press TRANSLATE, or press RANDOM. 2) Read the split: page = address ÷ 256, offset = remainder. 3) If the page is on disk you get a PAGE FAULT. It is loaded into a free frame. If RAM is full, the oldest page (FIFO) is swapped out.

> PAGE REPLACEMENT

WHAT IT SHOWS: When RAM is full and a new page is needed, the OS must evict a page. FIFO evicts the page loaded earliest. LRU evicts the least recently used page. OPTIMAL evicts the page needed furthest in the future. It cannot be built in real life, so it serves as the best possible benchmark.
HOW TO USE: 1) The default reference string (the page requests in order) and 3 frames are preloaded. 2) Pick an algorithm and press RUN. Green HIT = page already in RAM. Red FAULT = page had to be loaded. 3) Drag the slider to replay step by step. 4) Press COMPARE. With the defaults you should see FIFO = 15 faults, LRU = 12, OPTIMAL = 9.

> SEGMENTATION

WHAT IT SHOWS: Programs are split into logical segments (CODE, DATA, STACK) that can have different sizes. A logical address is a pair: (segment number, offset). The segment table stores each segment's base (start in RAM) and limit (size).
HOW TO USE: 1) Choose a segment and an offset less than its limit, for example DATA offset 100. Physical = base + offset. 2) Try DATA offset 450. The limit is 400, so the hardware raises a SEGMENTATION FAULT. 3) Watch the yellow marker move on the RAM bar.
Physical memory: 0 to 4095

> FIT STRATEGIES (CONTIGUOUS ALLOCATION)

WHAT IT SHOWS: Without paging, each process needs ONE continuous free block, called a hole. The OS picks which hole to use:
• FIRST FIT: the first hole that is big enough. Fastest.
• BEST FIT: the smallest hole that is big enough. Wastes least space, but leaves tiny slivers.
• WORST FIT: the largest hole. Leaves a big leftover that can fit later processes.
HOW TO USE: 1) Type 40 and press PREVIEW. Each strategy reports its choice without allocating. First fit picks the 100K hole, best fit picks the 50K hole (tightest fit), and worst fit picks the 200K hole. 2) Choose a strategy and press ALLOCATE. 3) Free a process to create holes. 4) Try 250K: it fails even though 350K is free in total. That is external fragmentation.
